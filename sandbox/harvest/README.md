# Review-guidance benchmark fixture

A synthetic, public fixture for measuring how well a tool extracts general guidance from a month of
pull-request review comments. Everything in it is invented: the repository `example/widgets`, the people
(`alice`, `bob`, `carol`, `dave`, `erin`), the bots' output, the code, the commits and the review text. It
describes no real project, organization or person.

## What it models

`example/widgets` is a small Python library that reads sensor CSV and NetCDF files and writes daily summary
products. Ten pull requests (#101 to #110) merged in October 2026. Most review threads open with an
AI-drafted finding posted under a person's login; the general principle usually sits in the person's plain
reply, and the same principle recurs on different pull requests in different words. The answer key labels the
guidance a careful human reader would take away.

## Layout

| Path | What it holds |
|---|---|
| `comments/pr-0101.json` ... `pr-0110.json` | One comment list per pull request, as `scripts/comment_list.py` writes it: an object with `pr` and `comments`, ordered by `created` then `id` |
| `labels.json` | The answer key: `themes`, `items`, `negatives` |
| `standard/review-rules.md` | A live rule ledger with R-001 and R-002 |
| `standard/decisions.md` | A decision ledger with D-001 |
| `runs/guidance-extractor-2026-11-05.json` | One `guidance-extractor` run on the ten lists, the slice `sandbox/README.md` "Harvest recall" scores |
| `clusters/clusters-2026-11-05.json` | A driver's clustering of that run's guidance tally, written by an agent that followed `skills/revise/harvest.md` "Clusters" and read only the tally, the ledger and that section, never this key |

Each comment has the keys `pr`, `id`, `url`, `author`, `authorship` (`human`, `ai-drafted`, `bot`), `kind`
(`thread`, `reply`, `review`, `comment`), `thread`, `path`, `line`, `created` and `body`. Its
authorship is as `scripts/record.py`'s `authorship_of` reads it (`docs/contracts.md`, "Authorship").
`tests/test_harvest_recall.py` holds the fixture to its shape: every quote in its comment, every
authorship as `authorship_of` reads it, every reply after its thread's opener, and every theme on
two pull requests or more.

Each label item names the comment it comes from, a verbatim `quote` of at most 40 words from that comment's
body, its `kind`, `signal`, `theme` (or null) and a one-sentence `principle`. Only people's words are labeled,
a reply an agent drafted for its poster included, as `guidance_tally.py` reads it.
An item that restates a rule already in `standard/review-rules.md` carries `covered_by`. `negatives` lists
person-written comments that are purely specific to their pull request.

## Traps it contains

- A person's reply that quotes an AI-drafted reply, attribution line included, behind `>`; it is still `human`.
- A person asking whether a description was generated by Claude; not guidance.
- AI-drafted findings that state a general principle; not labeled, since labels are people's words only.
- AI-drafted replies agreeing with a person.
- The pull request authors' AI-drafted replies declining or questioning T1, labeled as their own
  theme T9, which never joins T1's cluster.
- People restating the live rules R-001 and R-002; labeled with `covered_by`.
- Generic praise ("LGTM, thanks!"); not guidance.
- Replies holding both a pull-request-specific fix and a general principle; only the general sentence is
  labeled.
